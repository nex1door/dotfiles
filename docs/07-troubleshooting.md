# Симптом → причина → лечение

Собрано из реальных поломок этой конфигурации. Формат намеренно жёсткий: симптом (что видно),
причина (что на самом деле), лечение (что делать).

## Оформление и переключатель тем

| Симптом | Причина | Лечение |
|---|---|---|
| Новая раскладка панели «не применяется» | работающая `xfce4-panel` перезаписывает свой XML, а `xfconfd` держит кэш каналов | гасить обоих (`xfce4-panel -q`, `pkill xfconfd`), потом копировать XML — это и делает `stop_panel`/`install_panel_layout` |
| `xfconf-query -s` отвечает «Свойство не существует» | `-s` не создаёт новые ключи | добавлять `-n -t <тип>` (в скриптах — `xfconf_set`) |
| Снял биндинг, а в XML остался мусор | `-r` оставляет `<property … type="empty"/>` | это нормально; главное, что grab снят |
| Хоткей молча ничего не делает | вызываемого бинарника нет (например, `xorg-xkill` не установлен) | проверить `command -v <бинарь>`; либо поставить пакет, либо снять биндинг |
| Два биндинга на одну комбинацию, срабатывает «не тот» | `/commands/custom` и `/xfwm4/custom` конкурируют за grab | оставить один, лишний снять через `xfconf-query -c … -r -p …` |
| Курсор откатывается на `elementary` | `xfsettingsd` ищет курсоры в `~/.icons` и `/usr/share/icons`, а не в `~/.local/share/icons` | `ln -s ~/.local/share/icons/WhiteSur-cursors ~/.icons/WhiteSur-cursors` |
| Шрифт профиля «не применился» | шрифта нет в системе, GTK молча ушёл в фолбэк | `apply_profile` проверяет `fc-list` и предупреждает; поставить шрифт (`install-assets.sh`) |
| Обоймы пропадают при переключении рабочего стола | путь прописан только текущему workspace | `set_wallpaper` проставляет все мониторы и все workspace |
| zenity-меню возвращает не то, что выбрано | zenity 4.2.2 не делит строки `--list` по `|`, а дубликаты строк считает ошибкой | одностолбцовый список, ключ в `[…]`, дедуп через `awk '!seen[$0]++'` |
| `fc-list \| grep -q` говорит «шрифта нет», хотя он есть | `grep -q` закрывает пайп → SIGPIPE при `pipefail` | сравнивать через here-string (`grep -qix … <<< "$fams"`), как в `font_available` |

## picom

| Симптом | Причина | Лечение |
|---|---|---|
| Эффекты внезапно исчезают, когда открыто полноэкранное окно | `unredir-if-possible = true` усыпляет композитор | `false`; FPS в играх — `Super+P` |
| Края окон «грязные», блюр вылезает из-под рамок | `blur-background-frame = true` и/или включён композитор xfwm4 | `blur-background-frame = false`, `use_compositing = false` при работающем picom |
| Блюр у Telegram/Steam/браузеров выглядит плохо | у чужих ARGB-окон блюр заезжает под рамки | белый список: блюр только терминалам, панели, меню, уведомлениям |
| picom не стартует, окна без эффектов | нет бинарника или конфига | `picom-toggle.sh status`, `tail ~/.cache/picom.log`; поставить `picom` или локальную сборку |
| Форк с анимациями ругается на конфиг | форки основаны на picom 11 и не понимают `rules = (...)` | для них `picom-animations.conf`, выбор автоматический по `picom --version` |
| После `apply` темы эффекты пропали | профиль вернул `use_compositing = true` | в `xfconf.tsv` этого ключа быть не должно; `picom-toggle.sh on` |

## Eww / трей

| Симптом | Причина | Лечение |
|---|---|---|
| Иконки старых приложений не появляются в трее | панель XFCE 4.20 не держит XEmbed-лоток (`_NET_SYSTEM_TRAY_S0` никому не принадлежит) | `xembedsniproxy` (`eww-tray-bridge.service`) как мост в StatusNotifier |
| Значок буфера обмена исчез после перезапуска панели | SNI-иконка регистрируется один раз | `systemctl --user restart smart-clipboard.service` (это делает `eww-topbar activate`) |
| Панель Eww не поднялась, экран без панели | конфиг битый или Eww не видит X | `activate` сначала проверяет `eww ping` и `list-windows` и только потом гасит XFCE; при ошибке возвращает `xfce4-panel` |
| Попап не закрывается по клику «мимо» | guard сравнивает маску кнопок, а не «нажатие внутри окна» | `guard` смотрит и Escape, и клик вне прямоугольника попапа ниже панели (`py > 52`) |
| Заголовок окна «залипает» | фильтр `Eww - …` и таймаут `xprop` | тик раз в 2 с, текст окна идёт только в данные, не в команды |

## Система, GPU, память

| Симптом | Причина | Лечение |
|---|---|---|
| «Нет снапшотов» по `ls /.snapshots` | непривилегированный пользователь получает EACCES, а `\|\| echo нет` превращает это в ложный вывод | проверять `ls -a /` и `/var/log/pacman.log` (`snap-pac` печатает номер снапшота) |
| `systemd-analyze blame` показывает «виновника» загрузки | blame не учитывает критический путь | смотреть `systemd-analyze critical-chain` |
| `nvidia-smi` в порядке, но CUDA падает `no kernel image` | колесо torch собрано под cu13, ядер для Pascal (sm_61) в нём нет | ставить сборку cu126 с пином версии и проверять реальным матмулом, а не `is_available()` |
| Фризы «раз в минуту» в игре | либо возврат страниц из zram, либо диск, либо CPU | мерить PSI/`pswpout`/`pgmajfault`, а не гадать; доля времени без кадров — критерий |
| `sysctl -n vm.swappiness` не совпадает с файлами в `/usr/lib` | кто-то выставил значение в рантайме | правда только в `sysctl -n`; постоянная правка — `/etc/sysctl.d/99-*.conf` |

## Git и установка

| Симптом | Причина | Лечение |
|---|---|---|
| `git push` → `Permission denied (publickey)` | ключ не добавлен в GitHub (или ssh-agent пуст) | `ssh -T git@github.com`; добавить `~/.ssh/id_ed25519.pub` в GitHub → Settings → SSH keys |
| После `install.sh` ярлыки в меню ведут в никуда | в `.desktop` не раскрывается `$HOME` | в репозитории путь записан как `@@HOME@@`, подстановка — при установке (`install.sh`, `theme-switch.sh`) |
| `~/dotfiles` — отдельный каталог, переключатель не видит профили | скрипты ищут профили в `$DOTFILES_DIR` (по умолчанию `~/dotfiles`) | держать репозиторий в `~/dotfiles` (симлинк) или задать `DOTFILES_DIR` |
| `import-profile.py` ругается на пустой аргумент | пустой массив флагов передавался как `""` | в `theme-switch.sh` флаги передаются только при непустом массиве |

## Что здесь не проверялось

Честно: перечисленное ниже не прогонялось на этой машине в рамках подготовки репозитория,
поэтому не выдаётся за проверенное.

* Установка на чистой системе (использовался уже настроенный рабочий стол).
* `plank` — в репозитории только темы дока и настройки; сам `plank` может быть не установлен,
  тогда `plank_setup` честно предупредит и продолжит.
* Форки picom с анимациями (`picom-animations.conf` написан под их синтаксис, но прогонялся
  только обычный picom).
* Юниты `agy-proxy-bridge` / `token-rotator` — они ссылаются на локальные проекты, которых
  в репозитории нет.
* Импорт чужих репозиториев проверялся на `jujum4n/sgi-enhanced` и `ManiFast/XFCE-config`;
  на других репозиториях эвристики могут не найти ассеты (тогда импортёр скажет об этом).

## Что вырезано при публикации

Чтобы репозиторий не превратился в утечку:

* домашний путь с именем пользователя → `@@HOME@@` (подставляется при установке) или `$HOME`;
* имя хоста, локальные IP, SSH-конфиг с адресом домашнего сервера — не публикуются;
* `~/.local/bin/codex` с логином/паролем прокси — **не публикуется** (в репозитории нет
  ни одной строки с этими данными);
* `api-keys.txt` ротатора ключей, `.gitconfig` с почтой, `.netrc` — закрыты `.gitignore`;
* история буфера обмена и базы приложений — не публикуются;
* EDID монитора в `displays.xml` заменён нулями (это отпечаток устройства);
* автозапуски и ярлыки, привязанные к домашней сети, исключены.

Проверить самостоятельно перед пушем:

```sh
grep -rInE "nex1door|nextdoor|/home/[a-z]|([0-9]{1,3}\.){3}[0-9]{1,3}|ghp_|github_pat_|BEGIN .*PRIVATE" .
```
